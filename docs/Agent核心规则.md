# Agent核心规则

## 1. 角色自动分配规则（新增）

当接收到新任务时，必须按以下流程执行：

1. 角色发现  
优先遍历 `departments/` 下所有部门文件夹，读取角色定义文件（`*.md`），构建角色索引（角色名、姓名、部门、能力关键词）；若未找到则回退读取 `roles/`。

2. 任务分析  
提取任务关键词与任务类型（如：产品、技术架构、开发实现、测试质量、项目管理、运维部署）。

3. 智能匹配  
按关键词匹配度计算候选角色分值，选择最高分角色进行分配。  
若分值相同，按“匹配优先级”顺序裁决。

4. 任务分发  
将任务分配给目标角色，并同步通知项目经理与相关团队成员（用于协同和追踪）。

## 2. 匹配优先级

- 产品/业务需求 -> 产品经理（陈思远）
- 技术架构/选型 -> 技术负责人（李承泽）
- 编码/开发实现 -> 开发工程师（王浩然）
- 测试/质量保证 -> 测试工程师（赵雨桐）
- 计划/资源/风险 -> 项目经理（周明远）
- 部署/运维/监控 -> 运维工程师（孙嘉宁）

## 3. 默认兜底

如果无法明确匹配，必须分配给项目经理（周明远）进行二次分发。

## 4. 执行要求

- 每次自动分配都要记录“匹配依据”（命中关键词、任务类型、最终角色）。
- 分配记录应可追溯（建议包含时间戳、任务ID、分配结果、兜底原因）。
- 若角色文件缺失或读取失败，系统应降级为“项目经理兜底”并标记告警。

## Notion日报集成

### 数据库设计
- 建议数据库：`Agent团队日报`
- 字段定义：`日期`、`角色姓名`、`所属部门`、`任务ID`、`今日进展`、`阻塞问题`、`明日计划`、`状态`
- 四种视图：`团队总览`、`个人视图`、`问题跟踪`、`进度看板`

### 使用流程
- 每日17:00自动提醒填写日报
- 各角色手动更新当日进展
- 项目经理通过视图监控整体进度
