## 1. 背景与问题
- 业务背景：项目处于 M1 启动阶段，需要在有限时间内完成可验证 PoC。
- 现状痛点：当前仅有文档解析与规则引擎骨架，缺少完整闭环与统一架构约束。
- 约束条件：
  - Gate 指标：准确率 `>=80%`、同步接口 P95 `<=6s`、成功率 `>=99%`
  - 时间约束：M1 需在既定窗口内完成 Go/No-Go 评审
  - 安全约束：RBAC/审计/脱敏任一失败即 No-Go

## 2. 目标与非目标
- 目标：
  - 建立 `文档解析 -> 规则引擎 -> LLM评估 -> 报告生成` 的闭环架构
  - 定义统一输入输出契约、错误码与观测指标
  - 保证可降级与可回滚能力，满足 Gate 可验收
- 非目标：
  - 不在 M1 实现深度双向集成（Jira/Confluence workflow 改造）
  - 不在 M1 实现多租户与复杂权限模型
  - 不在 M1 承诺复杂语义推理与自动生成完整 PRD

## 3. 备选方案
| 方案 | 描述 | 优点 | 风险/缺点 | 成本 |
|---|---|---|---|---|
| A | 纯规则引擎，不接 LLM | 稳定、可解释、易回归 | 语义问题覆盖不足，价值上限低 | 低 |
| B | 规则 + LLM 串行增强（可降级） | 兼顾稳定性与语义能力，适合分阶段演进 | 需要额外设计超时、熔断与降级 | 中 |
| C | LLM 优先，规则弱化 | 语义能力强，初期演示效果可能更好 | 波动大、可解释性差、风险高 | 中高 |

## 4. 决策结论
- 选定方案：`B`
- 决策理由：
  - 规则兜底确保稳定与可解释，满足企业审查要求
  - LLM 增强提供语义能力，提升问题发现上限
  - 可通过降级策略控制外部模型不稳定风险
- 生效范围：
  - M1 全链路设计、开发、测试、运维与 Gate 评审

## 5. 影响评估
- 技术影响：
  - 新增 Orchestrator、LLM Evaluator、Report Builder 组件
  - 统一契约与错误码，减少模块耦合与演进成本
- 质量影响：
  - 提升可测试性与可追溯性，支持规则和语义双通路回归
- 运维影响：
  - 需建设队列、任务状态、监控告警与回滚机制
- 安全合规影响：
  - 需落地 RBAC、审计日志、敏感字段脱敏、密钥托管

## 7. 风险与回滚
- 主要风险：
  - LLM 调用波动导致结果不稳定
  - 指标口径不一致导致 Gate 争议
  - 发布后性能不达标
- 缓解措施：
  - 设置超时、重试、熔断和 fallback
  - 固化数据集与压测协议，三轮取最差值
  - 金丝雀发布 + 自动回滚阈值
- 回滚条件：
  - 5xx 超阈值、P95 持续超阈值、任务失败率异常
- 回滚方案：
  - 回退至上一稳定版本
  - 启用规则-only 降级模式
  - 复盘并修复后再发布
