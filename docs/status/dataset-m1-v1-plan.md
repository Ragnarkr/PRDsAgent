# dataset-m1-v1 构建计划（QA）

## 1. 目标与范围
- 目标：为 Gate-M1 提供可复现、可审计的准确率评测数据集。
- 适用任务：Week2 `1.1`、`1.3`。
- 版本：`dataset-m1-v1`（冻结后仅允许追加 `v1.x` 补丁，不覆盖原样本）。

## 2. 样本配额

| 文档类型 | 最低配额 | 建议配额 |
|---|---:|---:|
| Markdown | 30 | 40 |
| TXT | 30 | 40 |
| DOCX | 30 | 40 |
| 合计 | 120 | 120~150 |

补充要求：
- 每类样本需覆盖短/中/长文本（建议 3:4:3）。
- 每类样本至少包含 20%“难例”（术语歧义、冲突描述、边界条件）。

## 3. 抽样策略
- 来源分层抽样：历史需求库、近期增量需求、人工构造边界样本。
- 时间分层：近 3 个月样本不少于 50%。
- 去重规则：按 `title + normalized_content_hash` 去重。
- 代表性检查：抽样后按类型、长度、领域标签出分布图并复核。

## 4. manifest / hash 规则
- 根文件：`manifest.jsonl`（每行 1 条记录）。
- 必填字段：
  - `sample_id`
  - `doc_type`
  - `source`
  - `created_at`
  - `label_version`
  - `content_sha256`
  - `file_path`
- Hash 规则：
  - 原文文件计算 `SHA256`，写入 `content_sha256`。
  - 发布包再生成 `dataset_sha256`，写入 `RELEASE_NOTES.md`。
- 校验要求：
  - 导入前与评测前各执行一次 hash 校验。
  - 任一 mismatch 立即阻断评测并升级。

## 5. 双人抽检流程
- 标注模式：A 标注、B 复核、分歧由 QA 负责人裁决。
- 抽检比例：每类型至少 10%，且总抽检样本不少于 20 条。
- 一致性门槛：双人抽检一致率 `>=95%`。
- 不达标处理：
  - 一致率 <95% 时，回退到该批次重新标注并重新抽检。
  - 更新 `label_version`，保留变更记录。
