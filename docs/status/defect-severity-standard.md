# 缺陷分级标准（P0/P1/P2）与 Gate 测试节奏

## 1. 分级原则
- 按“业务影响 + 可恢复性 + Gate 阻断性”分级。
- 分级对象范围：M1 PoC backlog 内缺陷。
- Gate 截止时点：`2026-04-10 14:00`。

## 2. 缺陷级别定义

### P0（阻断）
满足任一条件即为 P0：
- 系统不可用或核心链路不可执行。
- 数据错误/数据丢失/安全失效。
- Gate 指标无法测量（含数据集不可用、脚本不可复现、统计口径无法执行）。
- 指标结果缺失关键字段，导致 Go/No-Go 无法判定。

处理要求：
- P0 必须立即升级，Gate 时点前必须清零。
- P0 不允许豁免；若存在未关闭 P0，则 Gate 结论必须为 `No-Go`。

### P1（高）
- 功能可用但关键能力受损，存在明确 workaround。
- 影响部分评测结果可信度，但不阻断全量测量。

处理要求：
- 需给出修复计划、负责人和时限；可在 Gate 后跟踪收敛。

### P2（中/低）
- 易规避问题，不影响 Gate 指标判定。
- 文档、提示文案、非关键流程缺陷。

处理要求：
- 纳入常规迭代修复，不影响 Gate 决策。

## 3. 判定示例
- “压测脚本跑通但未记录超时率” -> P0（指标不可判定）。
- “某类 DOCX 样本解析错误但有替代样本且总覆盖满足门槛” -> P1。
- “报告文案错字” -> P2。

## 4. Gate 前测试节奏
- 2026-04-06：冻结分级标准并宣贯。
- 2026-04-07：执行回归预跑，输出首版缺陷清单。
- 2026-04-08 16:00 前：完成首轮复测签收（硬检查点）。
- 2026-04-08 18:00：参与降级触发条件检查与决策。
- 2026-04-09：完成三轮 Gate 指标复测与复核。
- 2026-04-10 14:00：锁定 P0 与指标结果，提交 Gate 评审材料。
