## 技术风险点与替代方案（Tech Lead 结论）
1. 风险：`multipart` 依赖缺失会导致 API 启动失败。  
   替代方案：将 `python-multipart` 固定写入依赖清单（`requirements.txt`/`pyproject.toml`），并在 CI 增加启动探针。
2. 风险：dry-run 模拟结果会放大随机波动，可能误判真实稳定性。  
   替代方案：以真实 staging 三轮为主判定，dry-run 仅用于脚本链路自检。
3. 风险：压测口径在多角色间解释不一致（4xx、重试、分母口径）。  
   替代方案：冻结为统一计算配置（`latest_attempt`、`count_4xx_as_success=false`）并在报告中强制回显配置。
