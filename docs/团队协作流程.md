# PRDsAgent 团队协作流程（强制执行版）

## 1. 目的与范围
本流程用于确保所有角色在开始任何开发任务前，先完成统一文档阅读、流程理解与任务确认，避免返工与沟通偏差。

适用范围：
- PRDsAgent 项目全体成员（含开发、测试、产品、运营等全部角色）
- 从 M1 阶段开始的所有研发任务

## 2. 启动必读清单（Gate-0）
所有角色必须完成以下步骤，才能开始实际开发工作：

- [ ] 阅读 `docs/项目愿景.md`，理解项目目标、范围和阶段产出
- [ ] 阅读 `docs/Agent核心规则.md`，理解角色职责与任务分配机制
- [ ] 阅读 `docs/团队协作流程.md`，理解协作、汇报与验收机制
- [ ] 熟悉 Notion 日报数据库与字段填写规范
- [ ] 参加 M1 启动会议（北京时间 2026-03-23 09:00）
- [ ] 在 Notion 中确认角色信息（姓名、角色、负责模块、联系方式）

强制规则：
- 未完成 Gate-0 的成员，不得领取开发任务，不得提交代码，不得进入评审环节。
- 任务负责人（Owner）需在 Notion 中逐项核验并记录完成时间。

## 3. M1 启动会议强制要求
会议时间：
- 2026-03-23 09:00（Asia/Shanghai）

参会角色：
- 全体 6 个角色（如有新增角色，自动纳入）

会议议程（必须完成）：
1. 逐人确认 Gate-0 清单完成状态
2. 现场演示 Notion 日报填写流程（创建、更新、查询、筛选）
3. 明确里程碑、交付标准、时间线与依赖关系
4. 记录风险项与阻塞项，明确升级路径
5. 完成会后确认签署（Notion 勾选字段或确认页签名）

会议输出物（必须落档）：
- 会议纪要（包含角色确认状态）
- 任务分配表（Owner、截止时间、验收标准）
- 风险台账初版

## 4. 任务分配前验证机制（Gate-1）
在分配具体任务前，任务负责人必须要求角色完成阅读确认。

标准话术模板：

```text
@<角色名> 请先确认你已经：
✅ 阅读了项目愿景文档
✅ 了解了 Agent 核心规则
✅ 熟悉了 Notion 日报流程
✅ 参加了 M1 启动会议

确认后请回复：“已阅读并理解”。
收到确认后，我将正式分配 M1 开发任务给你。
```

验证规则：
- 未回复“已阅读并理解”的角色，不进入任务分配名单。
- 口头确认无效，以 Notion 或群内文本记录为准。

## 5. 日报与进度跟踪机制（Notion）
日报数据库：
- [PRDsAgent项目（日常跟踪）](https://www.notion.so/31a96011ac3e8066a73dd65ec5318cde?v=31a96011ac3e804cb25e000cfe8e1b49&source=copy_link)

最低更新要求：
- 每个工作日 18:00 前更新当日状态
- 状态至少包含：今日完成、明日计划、阻塞项、需要协助

字段建议（最小集合）：
- 角色
- 模块
- 状态（进行中/已完成/阻塞）
- 风险等级（低/中/高）
- 下一步动作
- 责任人
- 更新时间

升级规则：
- 阻塞超过 24 小时：升级给任务负责人
- 阻塞超过 48 小时：升级到项目负责人并记录处置方案

## 6. 开发与评审协同流程（执行层）
1. Gate-0/Gate-1 通过后，领取任务并确认验收标准
2. 在分支上开发并提交 PR（遵循 Conventional Commits）
3. PR 必须附带测试证据与回滚方案
4. 评审人按模板检查“文档阅读确认 + 注释规范 + 风险控制”
5. 合并后更新 Notion 状态并同步日报

## 7. 技术强制措施（仓库内落地）
为保证流程不依赖口头约定，必须配置以下机制：

1. README 顶部入门指引
- 明确“先读文档再开发”的入口和顺序

2. PR 模板强制确认
- 提交人必须勾选“已阅读项目文档与流程”
- 未勾选视为不合规 PR

3. 开发环境初始化提醒
- 在开发初始化脚本或入门步骤中，输出 Gate-0 提示

## 8. 例外处理机制
允许例外的场景：
- 紧急线上故障（P0/P1）需要先止损再补流程

例外补偿要求：
- 故障处理结束后 24 小时内补齐 Gate-0 确认
- 在复盘中标注“为何跳过流程、如何防止再次发生”

## 9. 沟通与执行话术
公告模板：

```text
各位角色请注意：

为确保项目顺利推进，所有成员必须先完成文档阅读和流程熟悉，
然后才能开始实际任务。这一要求用于降低返工和沟通成本。

请在 M1 启动会议（2026-03-23 09:00）前完成必读清单，并在会上确认。
未完成确认的成员将暂不分配开发任务。
```

## 10. 生效与维护
- 生效时间：发布即生效
- 维护责任人：项目负责人 + 流程管理员
- 更新原则：流程变更必须同步更新本文件、README、PR 模板
