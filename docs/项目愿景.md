# 需求文档Agent项目愿景（修订版）

## 1. 业务背景与问题陈述
### 1.1 当前痛点（基线）
- 需求评审经常因“验收标准不清、范围描述冲突、依赖遗漏”导致返工。
- 以近3个月项目统计作为初始基线（2025-12至2026-02，待在M0阶段复核）：
  - 需求返工率：24%
  - 平均评审周期：3.8天/条
  - 可测试验收标准覆盖率：71%
- 痛点影响：研发排期不稳定、测试设计反复、跨团队沟通成本高。

### 1.2 行业趋势与机会
- AI在需求工程中已从“摘要生成”进入“质量校验+风险提示”阶段。
- 公司内部已有Jira/Confluence等数据基础，适合先做轻集成与闭环验证。

## 2. 项目目标与价值主张
### 2.1 核心目标（SMART）
- 在2026-07-10（GA）前，将需求返工率从24%降至≤17%。
- 在2026-07-10前，将需求评审周期从3.8天缩短至≤2.8天。
- 在2026-07-10前，将可测试验收标准覆盖率从71%提升至≥90%。

### 2.2 价值主张
- 对产品经理：快速发现需求缺失与冲突，减少反复修改。
- 对开发团队：提高需求可实现性与边界清晰度。
- 对测试团队：输出可直接落测试点的验收建议。
- 对管理层：以指标化方式降低交付风险，提高迭代稳定性。

## 3. 范围定义（In-Scope / Out-of-Scope）
### 3.1 In-Scope（MVP）
- 输入：`Markdown`、`TXT`、`DOCX`。
- 能力：
  - 需求完整性检查（目标/范围/依赖/验收标准等必填项）
  - 验收标准质量评估（可测试性、原子性、量化程度）
  - 简单冲突检测（术语冲突、数值冲突、时序冲突）
  - 分析报告生成（问题分级、定位、修复建议）
- 集成：仅轻集成（导入/导出/链接回写），不做双向深度同步。

### 3.2 Out-of-Scope（MVP明确不做）
- 自动生成完整需求文档。
- 复杂语义推理与创新方案建议。
- Jira/Confluence的双向深度工作流改造。
- 中英以外多语言支持。

### 3.3 范围治理
- 新增需求若导致工期增加>1周或新增外部关键依赖，必须进入CCB评审。

## 4. 利益相关者与职责（RACI摘要）
- Sponsor：业务方向与阶段Gate决策（A）。
- PO：需求优先级与验收口径（R）。
- Tech Lead：架构路线与技术风险闭环（R）。
- QA负责人：质量门禁与评测体系（R）。
- PM：计划、风险、变更治理（R）。
- DevOps：部署、可观测性、发布与灾备（R）。

## 5. 成功指标与验收标准
### 5.1 业务指标（按月）
- 返工率 = 因需求问题重开工单数 / 总需求数，目标≤17%。
- 评审周期 = 需求创建到评审通过的中位时长，目标≤2.8天。
- 验收标准覆盖率 = 含可测试验收标准的需求数 / 总需求数，目标≥90%。

### 5.2 技术与质量指标
- 解析准确率（字段级）≥90%。
- 冲突检测F1 ≥0.85。
- 同步API性能：P95 ≤3秒，P99 ≤5秒。
- 异步任务：99%在60秒内完成。
- 并发能力：50并发稳定运行，100并发可降级不宕机。

### 5.3 采纳与满意度
- 试点团队采纳率≥60%，GA后全量采纳率≥80%。
- NPS（10分制）≥7。

## 6. 技术方案与非功能要求
### 6.1 架构原则
- 流水线分层：`文档解析 -> 规则检查 -> LLM评估 -> 报告生成`。
- 通过Model Gateway支持多模型切换、熔断、重试和降级。
- 采用异步队列隔离重任务，避免请求阻塞。

### 6.2 安全与合规
- 强制SSO/OIDC + RBAC（项目/文档粒度）。
- 传输TLS、存储加密、密钥托管与轮换。
- 敏感字段脱敏、审计日志全链路留痕。
- 上线前完成数据分级与合规评审（含第三方模型供应商条款）。

### 6.3 可运维性
- SLO/SLI体系：可用性、时延、错误率、队列积压。
- 发布策略：金丝雀发布 + 自动回滚阈值。
- 灾备目标：核心元数据RPO≤15分钟、RTO≤1小时。

## 7. 关键假设、风险与缓解
### 7.1 关键假设
- 团队愿意采用统一需求模板与评审口径。
- 现有历史需求可用于构建评测基线。
- 模型服务稳定性可满足试点阶段SLO。

### 7.2 主要风险与缓解
- 技术风险：模型效果波动。
  - 缓解：规则引擎兜底 + 离线评测集 + 回归门禁。
- 采用风险：用户习惯迁移困难。
  - 缓解：试点共创、分阶段推广、培训机制。
- 集成风险：外部系统依赖延迟。
  - 缓解：轻集成优先、连接器限流重试、死信队列。
- 安全风险：敏感需求泄露。
  - 缓解：最小权限、脱敏、审计、加密、供应商合规审查。

## 8. 项目依赖与前置条件
### 8.1 技术依赖
- 模型部署路线ADR（云API/本地/混合）定版。
- Jira/Confluence API权限与接口文档可用。
- 基础设施（计算、存储、网络、密钥服务）就绪。

### 8.2 组织依赖
- CCB变更机制与跨部门协作通道建立。
- 试点团队确认与培训计划落地。
- 项目预算和关键岗位（Tech Lead/QA/DevOps）到位。

- M2 MVP开发：04-13 ~ 05-22
- M3 内部试点与收敛：05-25 ~ 06-12
- M4 灰度与正式发布：06-15 ~ 07-10

## 10. 资源与预算（估算）
- 峰值资源：约9.6 FTE，平均7.5~8.5 FTE。
- 预算区间（18周）：人民币180万~260万。
- 预算结构：人力65%~75%，模型/算力12%~18%，质量保障6%~10%，安全合规3%~6%，培训与变更3%~5%，风险预备金10%~15%。

## 11. 阶段Gate（进入下一阶段的硬条件）
- Gate-M1：PoC准确率≥80%，同步P95≤6秒。
- Gate-M2：MVP功能完成率≥95%，P0缺陷=0。
- Gate-M3：试点采纳率≥60%，安全评审通过。
- Gate-M4：GA目标达成（准确率≥90%，P95≤3秒，并发≥50）。
